# 工程票 M4.1：补齐 zscore 原语

2026-08-06 立。前置：M4 闭环、M9 Atlas。

## 为什么是 zscore，而不是别的原语

不是猜的。接通真实 `claude -p` 之后的**两轮真实提案都用了 `zscore`**，而解释器把它
实现成恒等映射（已在上一票改为拒绝求值）。真实执行者反复要的东西就是缺口所在，
这是数据给出的优先级。

## 核心设计问题

`zscore` 要的是"输入步骤在过去窗口上的自身分布"，而解释器只持有原始序列，
且 `evaluate_spec` 一次只算一个决策时点。参考分布从哪里来？

**被否决的方案**：让 `evaluate_series` 在调用方请求的决策时点网格上算出全部步骤，
zscore 回看更早的网格点。否决理由是致命的：特征值会依赖**调用方请求了哪些决策时点**，
同一个 content id 在不同调用方处得到不同的数。内容寻址的承诺是"同内容必同语义"，
这个方案直接破坏它。

**采用的方案**：**采样网格由规格自己定义。**`Step` 新增两个字段，只属于 ZSCORE：

- `sample_every_seconds`：参考样本取自输入步骤在 `t - k * sample_every_seconds`
  （k = 1..window_seconds // sample_every_seconds）上的取值，严格取自过去；
- `min_samples`：最小**互异**取值数，低于它判为无定义。

求值改为惰性递归 `_value_of(name, t)` 并按 `(名字, 时刻)` 记忆化，记忆表在每次
`evaluate_spec` 内创建，不跨调用共享 —— 序列一换，同一个键就对应另一个数。

## 三个由此产生的连带修正

**一、门槛计互异取值，不计样本个数。**采样步长小于数据节奏时会反复读到同一批 bar：
实测在 SC 序列上，`sample_every_seconds=3600` 配 7 天窗口，可以出现 37 个"有定义"
样本只对应 2 个互异取值的行，标准差被压低因而系统性放大 |z|，而按个数计的门槛
完全无感。逐点的 `expected / defined / distinct` 聚合进 coverage 并入账 ——
参考分布被截断多少必须是证据的一部分，评价机的影响点闸门看不见它。

**二、覆盖准入：回看深度必须整段落在序列覆盖范围内。**否则声明为"20 日均值"的东西
在序列开头几天实际是"能取到多少算多少"的均值，同一份规格在完整序列与其截断副本上
给出不同的数且无从察觉。加了这道准入之后，**可求值蕴含值唯一**（有回归测试：完整
序列与其后缀在双方均准入的点上逐位相同）。代价是演示里最早的 153 个决策点由"有数"
变为无定义 —— 那正是被修正的缺陷本身，不得靠放宽检查让旧测试继续通过。
`BarSeries` 因此新增 `coverage_start`：源在这段时间**有覆盖只是没有 bar**，与
**这段时间根本没有数据**，是两回事，必须由数据提供方声明而不是由解释器猜。

**三、`required_lookback_seconds` 改为沿 DAG 累加。**zscore 的参考样本取到
`t - window_seconds`，而每个样本又把输入步骤的窗口再往前推一次。原实现逐步取 max，
把这个数写小，而它经 `describe()` 进账本，是审计记录与"历史数据是否够用"的依据 ——
写小了就是账本里的一句假话。

## 语言层新增的三条拒绝

- **派生步骤不接受 `offset_seconds`。**此前它被静默忽略。让它生效会使同一个
  content id 算出另一个数；拒绝则不改变任何现存规格的值。滞后写在叶子 window 上，
  那里它有确定语义。这同时消解了 zscore 采样锚点的歧义。
- **从 `output_step` 不可达的步骤一律拒绝。**惰性求值不会执行它们，而 `describe()`
  仍把它们的 source 写进账本：证据会声称本特征用了某个未接入的数据源，而那个数与它
  无关；一个够不到的 residualise 步骤更会让快照声称"已残差化"。
- **禁止 zscore 套 zscore。**对已标准化的量再标准化没有确定含义，且代价随嵌套深度
  指数增长。第一版的保守选择，错误信息里注明可重新审议。

## 版本与可回溯性

`FEATURE_SPEC_VERSION` 升至 0.2.0（新增字段必然改变全部 content id，旧证据与新证据
因此不共用 id），新增 `INTERPRETER_VERSION` 并进入 `EvaluationRequest.digest()` 与
`evaluation_result`：同一规格换一个解释器版本可能算出另一个数，证据必须能区分。
另加一条钉死 content id 字面量的金标测试，使 id 漂移可见而不是无声发生。

`STEP_SCHEMA` 同步更新，并新增一条断言它与 `Step` 必填集合一致的合同测试 ——
提示词漏写字段名导致合规模型被拒，已经发生过两次。

## 出口条件与实测

- `arad episode demo`：zscore 特征在真实 SC discovery 段上有定义 887/1040 点，
  每点期望 90 个参考样本、实测中位 84、最少 77；判 blocked，且**置换检验未通过**
  （36.5% 的置换斜率不小于实际值）。未标准化的版本此前 t 值 5.64 且通过置换，
  标准化之后不再通过 —— 原先的强度有一部分来自水平与趋势结构；
- `arad episode demo --provider claude`：真实 Opus 5 **首次输出即合规**（无
  `provider_repair` 事件，说明 schema 说明修复有效），产出 10 日/30 日均值之比再作
  126 天 z 标准化，830/1040 点有定义，走完评价判 blocked，阻塞项只剩"未声明成本模型"
  与"单品种双向 cluster 退化"两条已知结构性缺口；
- 全仓 ruff 与 pytest 通过。

## 本票不做

- `residualise` 仍抛 `StepNotImplemented`：残差化需要控制序列，解释器不持有它们；
- 求值期工作量上界（样本数已被 512 上限约束，接入 1 分钟 bar 后再议）；
- 允许 zscore 嵌套。
