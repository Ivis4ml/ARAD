# 工程票 M8.2：模型的选择必须真的算数

2026-08-07 立。前置：M8.1。触发它的是一句提问：「要让模型自己去里面选择」。
顺着这句话查下去，发现模型的选择此前是装饰性的。

## 事故

全部 12 条 Study（三次运行，跨两个 provider）都声明：

```
target = sc_rv_next_session       # 已实现波动，label_is_return=False，不可交易主张
universe = sc_dominant_t1
```

而评价机实际用的标签是：

```
target_name = sc_ret_next_session  # 有符号收益，label_is_return=True
```

**预注册的是波动幅度的假设，检验的是收益方向。**两者此前实测过，秩相关只有 −0.05
（方向近乎正交），量级相关 +0.46。也就是说，每一条已记录的结论都是关于模型
**没有问过的那个问题**。

成因是两处写死互相不知道对方：

- 菜单只列一个 target，且列的是 `FEATURE_TARGET`（`demo.py` 里那条只用于构造特征
  序列的表）；
- `_build_evaluation` 的标签写死取 `LABEL_TARGET`，`label_is_return=True`、
  `label_rule="entry_to_close"` 也一并写死。

没有任何检查比对提案声明的 target 与评价机拿到的 target。证据里两个名字各自都是
对的：`proposal_locked.target` 记着波动，`evaluation_result` 的 `target_name` 记着收益。
它们只是从不相互比对。

## 它还解释了 M7.3 底下更深的一层

模型被告知「目标是已实现波动」，据此提出幅度型特征 —— **对波动目标这完全正确**。
然后语义审计拿收益型目标的记录去比对，判它「幅度对方向」，连续七轮。
M7.3 修掉的散文子串匹配是真缺陷，但底下这一层才是根因：模型是对的，
是框架在目标这件事上对它说了假话。

## 三处改法

**一、硬检查，且在读 outcome 之前。**`run_round` 在 `record_outcome_read` 之前比对
`request.target_name` 与 `proposal.target`，不一致抛 `TargetMismatch`。
刻意抛异常而不是判 blocked：blocked 是一个**关于该 Study 的结论**，
而这里根本没有形成过一个可下结论的 Study —— 问的问题与检验的问题不是同一个。
有测试钉住此时统计分母仍为 0。

**二、菜单如实列出全部已物化的 target。**由 `TARGET_SPECS` 逐项导出真实记录
（`label_rule`、`label_is_return`、`tradable_claim`），只列已物化的。
选哪个是模型的经济判断，不是装配方的写死。

**三、标签由声明的 target 决定。**`_load_sc` 载入全部三张目标表
（实测 `sc_rv_next_session` 1040、`sc_ret_next_session` 1040、
`sc_open_gap_absorption` 919 行），`build_evaluation` 按提案选表，
`label_is_return` 与 `label_rule` 一并按所选 target 的记录取。
声明了没有物化的 target 抛 `UnknownTarget`。

语义审计的 `target_record` 同样改为按**声明的** target 取，
否则审计员比对的仍是特征与另一个目标的语义。

回调签名扩展为 `(feature, study_id, proposal)`，旧签名保持兼容。

## 对既有记录的影响

已记录的 12 条判决**按当时的实现成立，但它们回答的不是提案所问的问题**。
账本只增不改，这些记录保留；口径以 `EPISODE_VERSION` 区分（0.1.0 为旧语义，
0.2.0 起本票）。任何对它们的引用都必须注明这一点。

四条读过 outcome 的 Study（`auto-study-1` 至 `4`）的 null 结论是关于
**收益方向**的，而它们的机制文字写的是波动。这四条不应被当作「Polymarket 关注度
与原油波动无关」的证据。

## 实测

- `.venv/bin/ruff check .` 通过；`pytest tests/ -q`：**652 通过**（M8.1 后 650 + 2）；
- 新增两条测试：声明与被评不一致必须抛错、且抛错时统计分母仍为 0。

## 本票不做

- 让模型选 universe（品种）。M8.1 已把 `PRODUCTS` 由 1 增至 72，但 spine 尚未物化，
  `build_evaluation` 也仍只装 sc 的序列。universe 的选择要等 spine 建完；
- 一次调用产出 N 个候选（参考实现研究给出的方案，另立一票）。
