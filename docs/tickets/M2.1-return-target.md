# 工程票 M2.1：收益型 target，让 Sharpe 真正有定义

2026-08-06 立。前置：M2 Temporal Spine、M9.1 演化视图。

## 为什么

Atlas 的演化视图能画 Sharpe，但 Sharpe 一直是"未定义"：两个已有 target 的 label 都不是
有符号收益。`sc_rv_next_session` 是已实现波动（正的量级），`sc_open_gap_absorption`
是吸收比例且明确不作可交易主张。评价机按 `sign(prediction) * label` 构造策略收益，
label 不是收益，这条序列就不是任何策略的盈亏。

## 设计：入场在开盘后一分钟，不在开盘

新 target `sc_ret_next_session`，`label_rule="entry_to_close"`：

- **决策** = session 开盘前 60 秒（与既有 target 一致）；
- **入场** = 开盘后 1 分钟，取该分钟**最后一笔**（约 09:00:59）而不是第一笔。
  决策到成交需要时间，取本分钟最后一笔是保守的一侧；
- **出场** = session 收盘；
- **label** = log(出场价 / 入场价)。

集合竞价成交价不参与，因此**开盘跳空不在本目标的主张之内**。这是在遵守 M2 已记录的
一条假设：`sc_open_gap_absorption` 的描述写着"开盘价对决策时点而言不可执行"。
`label_start` 因此改为入场时刻而不是开盘 —— 这加强的是**可执行性**，不是防泄漏：
决策 08:59 本来就早于开盘 09:00。

## 无定义的六种原因

`no_ticks`、`zero_volume`、`no_entry_price`、`no_exit_price`、
`entry_at_price_limit`、`exit_at_price_limit`。

涨跌停按**逐价**判断而不是整段判断：入场那一刻锁在涨停就买不进，收盘锁在跌停就卖不出，
两者都使这条收益无法捕获，与整段是否锁死无关。

实测全史 1,816 行 → **有取值 1,782，无定义 34**（no_ticks 24 + 入场触板 6 + 出场触板 4）。

## 顺带修掉 M2 的一个 P1

`SessionBars.is_limit_locked()` 原本用**精确浮点相等**比对交易所限价。实测
sc2604 在 20260303 日盘整段 225 根 bar 收于 572.3，而限价字段是 572.3000000000002，
差 2.7e-13：`price in (upper, lower)` 返回 False，于是一个一手都买不到的 session
被物化成 `value=0.0, no_trade=False`。这直接违反 `targets.py` 自己的假设 5
「no-trade 一律是 NULL 加原因，绝不写 0.0」。

改为按**半个 tick** 容差逐价判断。RV 表的有取值行数因此由 1,789 降到 1,788，
`limit_locked` 由 3 升到 4。全库扫描确认只有两个 session 命中这个浮点缝隙，
其中一个进入了主力视图。

## 三条连带修正

**一、`sc_rv_next_session.tradable_claim` 由 True 改为 False。**本数据集里没有 SC 的
波动率工具，已实现波动是一个正的量级而不是可捕获的收益。原值为 True 属记录错误。

**二、`label_rule` 改为映射派发。**原实现是两分支 if/else 且 `else` 落在已实现波动上：
新规则只加进校验元组而忘了加分支时，会**静默地以新 target 的名义物化 RV**。
现在未注册的规则在构造期就被拒（有负向测试）。

**三、评价机拒绝对非收益 label 声明收益。**`EvaluationRequest` 新增 `target_name` 与
`label_rule`（都进 digest），`label_is_return=True` 而 `label_rule` 不在
`RETURN_LABEL_RULES` 里时抛 `LabelIsNotAReturn`。没有这道检查，`tradable_claim`
只是装饰：把 `label_is_return=True` 配一张已实现波动的表，评价机照样会出年化 Sharpe。
该常量在评价机与数据层各存一份（评价机不依赖数据层），有合同测试钉住两者一致。

## 年化系数

SC 一天两个 session，实测**每年约 485 个 session**，沿用教科书的 252 会把年化 Sharpe
系统性低估约三成。评价机从本次评价实际用到的决策时点导出 `periods_per_year_derived`
并与声明值并列输出；不一致**不阻断** —— 只覆盖夜盘的 Study 本就该导出更小的值，
而年化只是显示口径，不改变判决。

## Sharpe 的零假设带

`selection_band` 现在也给 `sharpe` 出带：`expected_max_sharpe(n, 本链 Sharpe 的标准差)`，
**单侧**（搜索只挑最大的那个，用双侧会把水平抬高约 10%）。尺度只能从实际试过的那些
试验估，因此至少要两次有定义的试验，第一版必然没有带。同时给出紧缩 Sharpe（DSR）：
观测值真正超过该基准的概率，低于 0.5 意味着与选择在噪声上挑出的最好值无法区分。

## 出口条件与实测

- `arad spine build` 从已物化的 bar 重建三个 target，13 秒，**不需要重读 1.37 TB 的
  tick 归档**；
- `arad episode demo --provider lineage` 五版链上 Sharpe 全部有定义：
  逐期 −0.035 → −0.010，年化 −0.77 → −0.23，DSR 全部低于 0.28；
- **换成收益型 label 之后曲线是往下走的**：|t| 由 5.03 降到 0.83，IC 由 +0.161 变成
  −0.014。波动特征能预测波动的**幅度**，不能预测收益的**方向**。这正是这一票的价值：
  之前那条漂亮的上升曲线量的是另一件事；
- 全仓 ruff 与 pytest 通过。

## 本票不做

- 交易成本与容量模型（M5）。Sharpe 全部标注 pre-cost，成本模型仍是 candidate 的硬闸门；
- 日盘/夜盘分开建模（实测收益标准差 143.5 与 92.1 个基点，差异显著，值得单独一票）；
- 多品种横截面，因此截面 IC 仍不可得。
