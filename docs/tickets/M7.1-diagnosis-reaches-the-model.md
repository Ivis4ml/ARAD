# 工程票 M7.1：环只对确定性变异器闭上了

2026-08-07 立。前置：M6、M7。触发它的是第一次真实模型自主运行的后三轮。

## 事实

8 轮里最后三轮的结局都是 `semantic_mismatch`，错配码**都是同一个**：

```
magnitude_vs_signed_label
特征度量的是幅度（标准差、绝对创新、已实现波动一类），而标签是有符号收益。
sign_unit 仓位下被检验的是方向，两者不是一回事
```

三轮分别提了 `rv_innovation_z_1d_vs_14d`、`pm_iran_belief_churn_innov_z`、
`cb_rv_short_over_base_z` —— 三个不同的构造，同一个语义错误。

原因在 `service.py`：

```python
if hasattr(provider, "mismatch_codes"):
    provider.mismatch_codes = learned
```

`mismatch_codes` 只有确定性变异器 `AutoProposer` 有这个属性。
`ClaudeCliProvider` 没有，因此 `hasattr` 为假，**累积的诊断被静默丢弃**。
M6 票把这条回传称作「环真正闭上的地方」，而它只对变异器闭上了：
真实模型每一轮都从零开始，无从得知上一轮错在哪。

审计本身是有效的：三轮都被拦下且**根本没读 outcome**，因此统计分母是 4 而不是 7。
损失的不是正确性，是三轮的时间与调用预算。

## 改法

诊断走**任务载荷**，不走 provider 属性。载荷这条路对任何 provider 都成立，
因为它最终进的是提示词，而提示词是所有 provider 共同的入口。

- `run_service` 把累积的 `learned` 写进入队载荷；
- `assemble_proposer_context` 新增 `learned_mismatches`，
  按封闭词表渲染成提示词里的一节，每条码附上 `SEMANTIC_MISMATCH_TAXONOMY` 的解释
  （码本身对模型没有意义），并明说「本轮的提案不得再犯同样的错配」；
- **未登记的码不渲染**。自由文本是把效应走私给下一版的通道，而这正是
  封闭词表存在的理由。有测试用 `"斜率为负且 t 值 -2.66"` 这样的字符串验证它不出现在提示词里。

累积而不是只取上一轮：一旦「幅度对方向」被指出来，之后就不该再退回幅度特征。
只取上一轮会让链在两种机制之间来回震荡，这在 M6 的离线实跑里出现过（A/B/A/B）。

## 为什么这不构成结果泄漏

错配码在**读取任何 outcome 之前**产生，只比对规格与目标的语义。
被拦下的那些版本根本没有读 outcome。词表是封闭的，且既有测试钉住
整张词表不含任何数字。因此这条回传不携带任何效应的方向或量级。

## 顺带修掉一个位置错误

`assemble(task)` 收到的是队列记录，业务载荷在 `task["payload"]` 下一层
（`episode.py` 读 `study_id` 与 `parent_study_id` 都走这一层）。
第一版写成 `task.get("learned_mismatches")`，恒为 None，测试立刻照出来了。

## 实测

- `.venv/bin/ruff check .` 通过；`pytest tests/ -q`：**633 通过**（M7 后 631 + 2）；
- 新增测试用一个**没有** `mismatch_codes` 属性的 provider 跑三轮，
  断言第一轮载荷为空、其后每一轮都带着 `magnitude_vs_signed_label`。
