# 工程票 M4.2：分位排名原语

2026-08-07 立。前置：M4.1 zscore、M6.2。动机是实测的，不是补全语言。

## 为什么

M6.2 只用 X 重算三条真实特征的杠杆时发现，`pm_geo_attention_share_z_iran_over_be_1d`
的最大杠杆是 **0.607** —— 单个观测占了回归元全部变异的六成，斜率由那一天决定。

当时的语言里没有任何稳健变换可用。`zscore` 是唯一的归一手段，而它在重尾输入下
有两种失效方式，方向相反：

| 离群日的位置 | zscore 最大杠杆 | zscore 极差 | rank_pct 最大杠杆 | rank_pct 极差 |
|---|---|---|---|---|
| 在**被评估的点**里 | **0.9714** | 4740 | 0.1071 | 0.99 |
| 在**参考窗口**里 | 0.1080 | **0.0046** | 0.1045 | 0.95 |

第一行：zscore 的取值本身重尾，一个观测占掉回归元 97% 的变异。
第二行：离群值撑爆参考分布的标准差，其余取值被压到几乎相同，
评价机会正确地报「回归元没有变异」，那一轮白花。

两种失效 rank_pct 都不发生：取值有界于 [0,1]，无论尾多重，任何单点的杠杆都被这个界约束住。

## 定义

`rank_pct` 与 `zscore` 共用同一张采样网格与同样的约束（`SAMPLED_KINDS`），
只是归一方式不同：

```
rank_pct = ( #{s < x(t)} + ½·#{s = x(t)} ) / n
```

其中 s 取自输入步骤在 `t − k×sample_every_seconds`（k = 1..window//sample_every）上的取值。
用中位秩的经验分布函数，平局各算一半，因此常量段不会被系统性地推向 0 或 1。
有一条测试用可精确算出的构造钉住这一点：参考样本恰为 1..40、当前值为 5 时，
取值必须是 (4 + 0.5)/40 = 0.1125，而「平局整个算小于」会给 0.125，「整个不算」给 0.100。

**它不是 zscore 的替代，是另一个假设。**代价是丢掉幅度信息：
「今天的关注度是常态的三倍」与「今天的关注度排在过去四十天的第 95 百分位」
不是同一句话。提示词里明写了这一点。

## 交叉嵌套一并拒绝

`_no_nested_zscore` 推广为对整个 `SAMPLED_KINDS` 生效。两个理由都与是哪一种无关：
对已经相对自身分布归一过的量再归一一次没有确定含义，
且求值代价随嵌套深度指数增长（每一层都要把整条输入链在整个采样网格上重算一遍）。

## 实测

- 生成代码与解释器在 rank_pct 上**逐位一致**（既有的 codegen 等价测试新增一条规格，
  跨 240 小时逐点比对，差值上限 1e-12）；
- `FEATURE_SPEC_VERSION` 0.2.0 → 0.3.0。新种类进入 `model_dump`，
  因此含 rank_pct 的规格与任何既有规格不共用 content id；
- 构造测试时踩到两条既有约束，两条都在正确工作，记录在此以免下次重踩：
  窗口右端点是开区间（PIT 纪律），正好落在采样时刻的 bar 会被排除，
  测试序列必须把 bar 放在采样点之前；门槛计**互异**样本数，
  只有 7 个不同取值的序列整条特征无定义；
- `.venv/bin/ruff check .` 通过；`pytest tests/ -q`：**640 通过**。

## 本票不做

- 不为 `max_leverage` 设阻断阈值（M6.2 已说明理由：它只捕到三条里的一条，
  而「一个点占多少变异算太多」是我无法在不看这些结果的前提下定下来的数）；
- 不改变任何既有规格。rank_pct 是新增选项，模型用不用是它的经济判断。
