# 工程票 M6.2：影响度量除错了分母

2026-08-07 立。前置：M3 评价机、M6.1。触发它的同样是实跑而不是设计推演。

## 事实

真实模型自主提出的前三条 Polymarket 特征全部被同一条理由拦下：

```
单点影响过大：最大 DFBETA 占斜率 9.72，超过预注册上限 0.5
```

把三条特征的回归元重算一遍（**只用 X，不碰任何标签**），得到的排序与闸门相反：

| Study | t | 最大杠杆（只用 X） | 旧闸门 \|DFBETA\|/\|β̂\| | DFBETAS = \|DFBETA\|/SE |
|---|---|---|---|---|
| auto-study-1 | −0.030 | 0.022 | **9.72** | 0.29 |
| auto-study-2 | −0.258 | **0.607** | 4.84 | **1.25** |
| auto-study-3 | −1.093 | 0.119 | 0.72 | 0.78 |

study-1 的最大杠杆是 0.022，即最有影响的那个点只占回归元总变异的 2%。
它没有被任何单点主导。它的 DFBETA 占比之所以是 9.72，只因为分母
（斜率 −6.7e-06）几乎是零。

## 缺陷本身不需要数据就能论证

`|DFBETA| / |β̂|` 在 `β̂ → 0` 时发散。因此这道闸门在**完全没有效应**时最响，
而那正是不存在任何「被单点主导的结论」的情形。它报出的理由在那里是假的。

真正被单点主导的是 study-2：一个观测占了回归元变异的 60.5%。旧闸门把它排在
study-1 之后。

## 改法

标准化用**斜率的标准误**而不是点估计，即 Belsley-Kuh-Welsch 的 DFBETAS。
分母取本次推断实际使用的标准误（双向 cluster），因此这句话读作
「删掉这一个观测，估计移动多少个我们实际用来做推断的标准误」。

阈值取 `|DFBETAS| > 1`。理由是先验的、与本仓库数据无关：BKW 同时给出
`|DFBETAS| > 1` 与 `2/sqrt(n)`，后者是用于**筛出待人工检视的点**的大样本阈值
（n = 506 时为 0.089，会把上表三条全部标出），而这道闸门是用来**阻断**的，
因此取尺度无关的那个读法：一个点把估计移动了整整一个标准误。

**必须记录的一件事：写下这个阈值时，我已经看过上表三个 DFBETAS 值。**
因此不以「它恰好把三条分开」作为理由。阈值选择在已有记录上是否可能改变结论，
单独查证如下。

## 阈值选择在已有记录上是无效应的

扫全部四个账本（`arad.db` / `lineage.db` / `episode_demo.db` / `service.db`），
共 4 次评价，全部来自 service.db。四条的 `blocked_reasons` 除影响度量外
各有 3 条其他阻塞理由，其中「未声明成本模型：不得取 candidate」对每条都成立
（M5 未做，成本与容量模型不存在）。**仅靠影响度量阻塞的：0 条。**
因此无论阈值取 1 还是 `2/sqrt(n)`，没有任何已记录判决的结论会改变。

四条的 DFBETAS 为 0.289 / 1.248 / 0.782 / 0.567。该运行仍在继续，其后续轮次用的是
修改前的评价机（进程已导入旧代码），因此这个计数在运行结束后要重新查一次。

## 同时新增的两个诊断量，都不阻断

- `max_leverage`：DFBETA 里不含残差的那一半，**只依赖回归元**，因此读标签之前
  就可算。有测试钉住它对同一组 X、两组不同残差给出相同取值；
- `dfbeta_over_slope`：旧口径原样保留并报出，既保留与既有记录的可比性，
  也让「它为什么曾经触发」在账本里能被看见。

不为 `max_leverage` 设阈值：它只捕到三条里的一条（study-2），而「一个点占多少
变异算太多」同样是一个我无法在不看这些结果的前提下定下来的数。留作诊断。

## 差点把同一个病灶挪个位置

第一版改法在标准误不可用时（cluster 方差非正，或退化维使其为 NaN）取
`float("inf")`，于是账本会写下「删掉最有影响的一个观测，斜率移动 **inf** 个标准误」，
紧挨着另一条说 cluster 方差不可用的理由 —— 把**度量失败**报成关于特征的实质发现，
与本票要修的是同一类错误。这四轮没触发只因为标准误恰好正常，测试与实跑都没照到。

改为：标准误不可用时该量**无定义**（NaN），闸门不触发，并单记
`influence.gate_evaluable=false`。「没量出来」与「量了而且通过了」必须能区分：
后者是关于特征的结论，前者只是说这次量不出来。有强制 NaN 标准误的测试钉住。

## 契约有没有真的送到模型手里

M6.1 的单元测试钉的是常量与 `ProposalOutput.model_fields` 一致，钉不住它**有没有被
渲染进发出去的那份文本**，而原来的缺陷恰恰是「契约存在但模型看不到」。
补一条测试渲染真实提示词并在其中查找 `整数，只能是 1 或 -1` 与 `positive`。

## 实测

- `EVALUATOR_VERSION` 由 0.1.0 升至 0.2.0（`EvaluationRequest` 的参数改名，进 digest）；
- 既有的 `test_single_influential_point_blocks_candidate` 在新闸门下**仍然通过**，
  即真正的单点主导照样被拦；
- 新增三条测试，其中一条用纯噪声复现了事故形态：`make_rows(seed=7)` 的
  t = −0.059，旧口径 11.86，最大杠杆 0.155，新闸门不触发；
- `.venv/bin/ruff check .` 通过；`pytest tests/ -q`：**624 通过**（M6.1 后 619 + 5）。

## 本票不做

- 重尾回归元的盲化反馈通道。M6.1 把它记为阻塞事项时，前提是「重尾能在读标签
  之前看出来」。上表否定了这个前提的普遍性：study-1 的 DFBETA 膨胀来自残差而不是
  杠杆，只用 X 的通道看不见它。该阻塞事项据此修订：只用 X 的通道能捕到 study-2
  那一类（杠杆 0.607），捕不到 study-1 那一类，因此它是一个部分手段，不是解法；
- `rank_pct` 之类的稳健原语（新 StepKind、解释器分支、codegen、回看语义），另立一票。

## 暴露出的更大一件事，另行裁定

`kernel.py` 的判决导出是 `verdict = BLOCKED if blocked else CANDIDATE`，
因此 `Verdict.NULL` **从未被任何代码路径产出过**，而词表注释写着「五个值，
全部是合法完整产出」。auto-study-1 的 t = −0.030、置换检验 0.980、506 行有效样本，
这是一个干净的、有功效的否定结论 —— 整套系统存在的理由正是让这种结论可信 ——
它却被记成 `blocked`，词表里的意思是「判不出来」。

成因是 `cost_model_declared=False` 对每一条 Study 都成立，于是一个否定结论与一个
真正无法判定的 Study 在账本里无从区分。这与 M6.1 修掉的停滞误判是同一类归因错误。
