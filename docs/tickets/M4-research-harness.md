# 工程票 M4：Research Harness（LLM 作为执行者）

2026-08-05 人类裁决产生。前置：M3 三块（账本、评价机、durable queue）已交付。

## 定位纠正

在此之前的工作建的是**确定性的一半**（数据合同、PIT spine、账本、评价机、队列），
LLM 面向的一半一行都没有。本票补上后者。

**执行者是 LLM**，通过 `claude -p` 接入（当前选择 Opus 5 extra-high，可替换）。
harness 的职责不是替它做研究，而是让它的产出**可信且可累积**：

```text
初始化 → 产出 → 验证 → 反馈 → 迭代 → 记录
                                        └→ 可视化（M9 Atlas）
```

## 两条已裁决的约束

**一、worker 产出：结构化规格为主，可执行代码为辅，但代码必须附带清楚的表达。**

规格是一等工件：它进冻结锁、进账本、进 Atlas，是被审计的对象。代码只是规格的实现。
因此：

- 每次 worker 产出**必须**包含一份 `FeatureSpec`；
- 代码是**可选的**，但一旦提交，必须与其规格一致，且两者各自内容寻址；
- 规格与代码不一致按缺陷处理，不是"以代码为准"。

这条同时决定了 harness 需要沙箱（因为允许代码），也决定了沙箱不是唯一路径
（因为规格可由确定性解释器执行）。

**二、第一版目标：闭环跑通 + M9 Atlas 最小版本。**

环要转起来，人要看得见。预期第一版的判决全是 `underpowered` 与 `blocked` ——
这符合 Merge-Plan-2 §10 M4 的出口条件（四种 verdict 任一都算平台成功），
目的是暴露"我想象出来的边界"与"真实需要的边界"之间的差距。

## 范围

### 第一块：特征规格语言与解释器（本次交付）

PIT 安全必须是**结构性的**，不是被检查出来的：解释器在语言层就无法表达前视。
全部窗口都定义为"结束于决策时点之前"，没有任何原语能引用决策时点之后的数据。

### 后续块

- **provider 适配层**：`claude -p` 的模型无关封装，含 mock 模式使循环可在
  不消耗调用的前提下端到端测试；
- **上下文组装器**：按角色生成盲化 prompt。角色隔离在这里变成**进程隔离** ——
  proposer 与 interpreter 必须是两次独立调用，共享上下文即泄漏；
- **输出合同**：结构化 schema + 解析失败的重试与降级（坏 JSON 不丢任务，queue 已就绪）；
- **反馈格式化器**：失败分类、功效与覆盖，不含任何效果字段；
- **循环驱动**：Search Episode = 一段有调用预算上限的序列，预算耗尽即结束 Episode
  并把剩余预算交回 Program；Service 不停；
- **代码沙箱**：内容寻址、独立 worktree、隔离执行、资源上限（§7.3 禁止破坏性回滚）；
- **M9 Atlas 最小版本**：只读投影，从账本渲染总览、Study 时间线与判决快照。

## 不做

- 不让 LLM 计算 verdict —— 它只提案与解释，判决由评价机出具；
- 不在 prompt 里出现 β/t/p/IC/Sharpe；
- 不预设第一版会产生 candidate。

## 出口条件

- 一次 Episode 能在无人干预下走完「提案 → 冻结 → 特征 → 评价 → 判决 → 入账」，
  且全过程可从账本回放为自包含快照；
- 负向测试：规格语言无法表达前视；prompt 组装泄漏效果字段即失败；
  proposer 与 interpreter 上下文串用即失败；预算耗尽结束 Episode 而非停服务；
- Atlas 能把这次 Episode 讲清楚；
- 全仓 ruff 与 pytest 通过。
