# 票外问题记录

写报告的数学章节时，为保证每条公式与实现逐字一致而对代码做了一次系统提取，
过程中发现下列问题。它们都在当前票（报告）之外，**记录而不修**，等人决定。

## B1（真缺陷）· 驾驶舱同一屏上有两个口径不同的 n

`src/arad/atlas/live.py:237-265` 的 `_curve` 用 `evaluation_result` 事件的
1-based 序号 `i` 喂给 `expected_max_abs_z(i)` 作为该点的零假设带，而该 SQL
**没有 family 过滤**，是跨族累计；同一文件 `:396-404` 的 price 块却按 family
过滤 `statistical_denominator` 来算 `floor_now`。

后果：驾驶舱曲线上的地板与顶栏显示的地板来自两个不同的 n。当前只有一个族在跑，
两者数值接近，但口径不同这件事本身会在多族时给出错误的图。

修法方向：`_curve` 改为按 family 过滤，并与 `statistical_denominator` 同源计数
（即只计真正读过 outcome 的，而不是所有 `evaluation_result` 事件）。

## B2（文档与实现不符）· `search_price` 的 note 写着 √(2 ln n)

`src/arad/memory/induction.py:83-97` 返回给提案器的 `note` 字段说地板按
√(2 ln n) 抬升，而实现是 Bailey & López de Prado 的两项闭式。渐近主项与实际值
在小 n 时差别可观（n=10 时 √(2 ln 10)=2.146，实际 1.901）。
提案器读到的是错的口径。已在 docs 内更正同一说法，但代码里这一处未动。

## B3（措辞与所算的量不是一回事）· 「线性效应保留率」

`src/arad/registry/specs.py` 的 `_status` 用 |t_sealed| / |t_discovery| 与
`_HOLD_RATIO = 0.35` 比较。分子分母都是 **t 值**而非效应量，而两段样本量不同
（run11-study-3 为 616 行对 405 行）。即便斜率与残差标准差完全不变，
t 也会按约 √(405/616) ≈ 0.81 缩小。因此该比值不等于「效应保住了多少」。
报告已按此更正措辞并给出样本量修正后的估计。**裁决结论不变**
（修正后约 21.7%，仍远低于 0.35）。

## B4（无出处的常量）· `_HOLD_RATIO = 0.35` 与 `min_rows = 120`

两者都写死在 `registry/specs.py`，全仓各只用一处，且**没有任何文档给出推导** ——
不是由功效分析、样本量比或先验收缩推出的。修改它们不会重算已写入账本的开封记录，
但因子卡 status 是每次读取现算，卡片结论会随之改变。

## B5（判定只用区间起点）· `taxonomy_clean`

`registry/specs.py:149-153` 的 `overlaps_outcome_window` 只比较区间**起点**与
归纳语料切点，完全忽略终点：一个完全早于切点的区间同样被判为重叠。
对当前结论是保守方向（更容易判为污染），但判据本身不精确。

## B6（束被基线假象占位）· beam 按原始 |t| 排序，封存队列轮不到真候选

`beam.py` 的 Candidate 按 reward 排序本应自罚，但四个波动假象（|t| 9.30/8.87/4.89/4.57，
评价时地板仅 2.2 左右）的 reward 高达 +7.1 至 +2.3，永久霸占 width=4 的全部束位。
run16-study-3（纯 PM、已残差化、reward +1.79 —— 现代闸门时代唯一为正者）排第五，
恰好被挤出，run16 收尾的 sealed_pass 因此只重试了四个早已开封的老面孔（全部被拒）。
修法方向：束位按「来源 × 是否残差化」分层，或 Baseline Control 构造不占束位
（决定 0002 本就规定它们不计入另类清单）。
