# ARAD 最终形态定义

> ARAD = Autoresearch on Alternative Data。
> 本文档回答一个问题：这台机器做完之后，到底是什么。

---

## 1. 一句话定义

**ARAD 是一台长期运行的因子研究机器：它以中国商品期货为标的，以 Polymarket、
财联社新闻与期货自身量价为原料，自主地提出、检验、注册、监控和替换预测因子，
其产品是一个每个成员都带完整证据链的"活性因子库"。**

它不是一个回测脚本，不是一次性研究项目，也不是一个策略。
它是一条研究生产线加上一个不断被维护的库存。

## 2. 三层形态

### 2.1 产品层：活性因子库（Active Factor Library）

最终交付物是 `registry/features/` 下的一组因子对象。每个因子：

- 是一个完整的 Feature Object：经济假设、预期方向、预测视界、适用品种域、
  数据来源与可得时间、失效条件、计算代码、参数；
- 带完整判决证据：预注册记录、五关检验结果、正交性报告（相对基线因子库与库内其他因子）、
  成本后净收益、子区间稳定性、所属实验家族与多重检验修正；
- 带生命状态：`production / degraded / retired`，以及监控历史（滚动 IC、相关性漂移、衰减分解）;
- 可被下游直接消费：统一接口输出逐日品种截面得分，或声明的事件/波动类信号。

库不是只增的。因子会退化、会被替换，退役因子保留全部历史作为失败模式知识。

### 2.2 系统层：研究生产线

一条从想法到退役的完整流程，全部环节由 Claude 智能体在受约束协议下执行：

```
假设积压（盲提案补充）
  → 可行性预检（数据覆盖、n_eff、MDE 对经济上限）
  → 假设锁定（方向、视界、终点、预算，时间戳不可覆盖）
  → 原型（最简版本，sanity check）
  → 验证（五关判据 + 正交性 + 成本 + 稳健性 + 家族记账）
  → 判决（SHIP / ITERATE / KILL / ARCHIVE；null 与 underpowered 是合法完整产出）
  → 注册（写入因子库或失败档案）
  → 监控（衰减、漂移、相关性上升）
  → 退役与替换
```

关键结构约束（每一条都对应旧系统一个已发生的失败）：

- 评价机只读（防指标操纵与前视）；
- 提案者只见功效账本，不见效应数字（防 HARKing）；
- 循环的全部状态在注册表文件中，产出即下一轮输入（防"扩展后中断"死结）；
- 覆盖判定带数据增长重开条件（防搜索空间用完即止）；
- 底层调用失败计数可见（防静默退化为随机搜索）；
- 改进必须超过实测噪声底（防拟合噪声）。

### 2.3 运行层：两个模式，永不自停

- **挖掘模式**（初始）：循环持续运行，目标是第 3 节的库存覆盖目标。
  智能体不得以任何理由自行停止；想法枯竭时的继续路径已在协议中预先给出
  （读失败档案、重开 underpowered、换机制族、换终点、换数据源、做交互项）。
- **维护模式**（里程碑一达成后）：定期运行。监控在役因子、裁决前向留出队列中的候选、
  替换退化因子、继续扩大正交因子集、执行数据更新。

系统只被人类中断。"任务完成"不存在，只有"里程碑达成，转入下一模式"。

## 3. 库存覆盖目标与成功判据

> 本节按 `Merge-Plan-2.md` §3 与决定 0002 修订：因子数量是**库存覆盖目标与
> 调度优先级**，不设期限承诺，不是服务停止条件，更不是放松证据门槛的理由。
> 数据无法支持时，库存长期保持 0 至 4 个 production 同时持续产出可信研究信息，
> 也是系统的正常状态。

**库存覆盖目标：Alternative Factor Inventory 包含 5 个低相关的 production 因子**，
计数口径为新增信息来自另类数据源（Polymarket 或财联社新闻）或其与期货状态的
事前声明交互；纯量价因子属于 Baseline Control Library，只作对照不计数。
每个 production 因子满足：

1. 有明确经济机制与预注册方向，且实测方向一致；
2. 通过五关判据（可识别、显著、过影响点、符号正确、量级可信），
   多重检验修正基于完整实验家族（统计分母含全部读取过 outcome 的变体）；
3. 历史 validation 通过后仅获得 Candidate 资格；**升级 production 的唯一依据是
   该 Study 冻结之后新到的真正前向数据**（per-Study forward eligibility，
   由独立评估器一次性裁决）；
4. 相对 Baseline Control Library 与库内其他因子（含跨源）的残差信息显著，
   两两相关低于阈值；复合信号通过腿分解（增量不得全由标的自身量价腿承载）；
5. 在声明的视界上成本后净收益为正（横截面因子按分位多空扣双边成本；
   波动/风险类因子按其声明的用途给出可用性证据并标注不适用成本关）；
6. 库存整体至少覆盖两个机制族与两个时域，并报告源构成
   （polymarket / news / mixed），防止五个因子实为同一信息的五种写法。

达到覆盖目标后切换为"维护优先"模式，Research Service 继续寻找增量与替代项。

**里程碑二（维护模式的常态判据）**：每个在役因子有活的监控记录；
退化因子在触发阈值后 N 个循环内完成替换评估；前向留出队列的候选按预约日期得到裁决。

## 4. 明确不做什么（Non-goals）

- **不做组合管理与实盘执行**。产品止步于因子库与其证据；权重分配、风险预算、
  下单执行是下游系统的职责。
- **不承诺在某个特定数据源上一定找到因子**。承诺的是流程与总量：
  因子空间足够宽（量价 + 新闻 + Polymarket），里程碑一在文献先验下是现实的；
  但"Polymarket 必须出因子"这类源级承诺会重演旧系统被迫放松判据的压力。
- **不做分钟级方向性高频策略**。已被 2,742 项检验与成本分析系统性否定。
- **不在出现候选之前建设完整执行仿真**（盘口成交、涨跌停状态机等），
  成本模型从简单假设开始，随候选出现逐步加细。
- **不追求单因子最高夏普**。正交性与组合边际价值优先。

## 5. 为什么这一次能找到因子

这个问题必须诚实回答，因为前两个系统的名义结论都是零产出。

1. **样本约束解除**：909 个交易日对 125 天，功效提高约 7 倍，
   旧系统 78% 因样本不足跑不起来的检验重新可行；
2. **战场选择正确**：日频横截面（约 50 品种 × 900 日）替代单品种分钟时序，
   n 从几十升到数万量级；旧数据中唯一 t > 4 的可交易方向性证据正是截面框架；
3. **因子空间放宽**：另类因子空间同时覆盖 Polymarket 与新闻两个源及其与期货状态的
   交互；经典商品因子谱系（动量、期限结构、持仓、成交量）作为 Baseline Control
   Library 提供正交性标尺与流程演练，但不计入主目标，也不构成"必然找到因子"的保证；
4. **正面种子已在手**：闭市吸收的截面识别（RankIC 0.185/0.261）、中东主题对 SC 的
   独立增量（t=4.94）、tension 对波动（t=−4.40）、钱包技能表，
   都是等待条件化与工程化的具体起点；
5. **失败模式已知**：两个前代系统的全部结构性缺陷（循环死结、前视入池、伪重复、
   噪声无控、留出集死结）都有明确的对应修复，写入了协议与代码边界。
