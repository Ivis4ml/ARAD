# 决定 0010：研究员进程封闭化、方法说明显式装载、搜索覆盖表

- 日期：2026-08-15
- 状态：已实施（M17 / M17.1）
- 触发：用户提出三点 —— `claude -p` 没有用好、应当有一份可迭代的方法说明（skill）、
  以及「为什么只看伊朗轴，autoresearch 应该试任何可解释的组合」。
  核查这三点时发现一个此前未被记录的结构性漏洞（见第一节）。

## 一、研究员进程此前不是封闭的

实测（2026-08-15，`claude -p` 的 init 事件回报）：默认调用给研究员的工具包括
`Bash`、`Read`、`Write`、`Edit`、`Task`、`WebSearch`，外加全部已连接的 MCP 服务器
（Gmail、Notion、Slack、Figma 等），工作目录就是仓库根。

也就是说，盲化角色在原理上可以自己去读 `data/ledger/service.db`，
把全部判决、t 值与封存结果取回来。`assert_blinded` 扫的是 prompt 文本，
管不到模型自行取回的东西 —— 闸门在的位置根本拦不住这条路。

同一形态的第二条通道：用户级 `CLAUDE.md` 会被读进研究员上下文。
它的内容无害（中文文体规则），但它从未进过账本，也从未过闸门。

**过去的调用是否真的用过工具，无法追认**：provider 当时既不记 `num_turns`
也不记 `tool_use`。只能如实陈述：能力一直在，且未被记录。

### 处置

`ClaudeCliProvider` 的默认参数改为封闭形态，四条逐一实测核对过 init 事件的回报：

| 参数 | 作用 | 实测结果 |
|---|---|---|
| `--disallowed-tools <37 项>` | 拒绝全部工具 | `tools: []` |
| `--strict-mcp-config` | 不加载 MCP 服务器 | `mcp_servers: []` |
| `--disable-slash-commands` | 不加载任何 skill | `skills: []`、`slash_commands: []` |
| `--setting-sources ""` | 不读用户级与项目级设置 | 用户级 CLAUDE.md 不再进入 |

拒绝清单会过期（实测：拒掉一批之后 `Glob`/`Grep` 才冒出来），因此真正的保证不是清单，
而是**用 CLI 自己的回报做断言**：init 事件报出任何工具、MCP 服务器或 skill 即中止调用
（`require_hermetic`，默认开）。同时把 `num_turns` 与 `tool_use` 记进证据 ——
研究员进程若曾多轮，那是盲化事件，不是实现细节。

## 二、方法说明（skill）：显式装载，不用目录发现

用户要的「一个可迭代更新的 skill」采纳，但**不走** Claude Code 的 `.claude/skills/`
自动发现。理由与第一节同类：那是一条环境通道，任何人往目录里放一个文件，
研究员的上下文就变了，而账本对此一无所知、闸门也扫不到。

实施形态：

- 文件 `configs/skills/arad-proposer.md`，带 frontmatter（skill_id / version / role /
  update_rule）。
- `harness/skills.py` 读成字符串 → `assert_blinded` → 算内容指纹 → 作为
  `ProviderRequest.system_prompt` 发出 → 指纹进 `context_assembled`。
- `ProviderRequest` 新增 `system_prompt` 字段，**并进 `request_id` 的内容寻址**：
  同一段 prompt 配不同版本的方法说明不是同一次调用。
- 修复重试时两段文本都重新过闸门。

**更新规则（写进文件自身的 frontmatter，装载时核对）**：
方法说明只能承载**机械失败**的教训 —— 解析失败、schema 不合、事前功效筛拦下、
语义审计判不一致，全部发生在读取结果之前。任何来自判决的教训都不得写入，
那会使它成为结果回流通道（决定 0006）。`update_rule` 不是
`mechanical_failures_only` 即拒绝装载。

第一版内容取自实测的机械失败：`direction` 写成词、声明缺口时漏 `mechanism`、
自创契约外的键（`title`/`intent`/`minimal_ask`）、给派生步骤加 `offset_seconds`、
把 JSON 包进 markdown 代码块。run26 的 20 轮里有约四分之一耗在这类失败上
（3 次 provider 修复、1 次解析失败、1 次上下文拦截）。

## 三、为什么只看了伊朗轴：三个数字

| 维度 | 实测 | 说明 |
|---|---|---|
| universe | 196 条提案里 119 条 `sc_dominant_t1`、50 条面板 | 51 个品种有目标表，用过的不到十个 |
| target | 只用过 3 个（rv 116、ret 68、吸收 12） | 目标族本身只有三个 |
| 族 | 1,998 个候选族里只有 23 个被引用过；`cand:iran` 独占 96 条 Study | 单个组合 `cand:iran × sc × rv` 就有 34 条提案 |

原因不是模型偏心，是它**看不见自己走过哪里**：菜单每轮给 30 个族，
但没有任何东西告诉它哪些组合已经问过多少次。

### 处置一：搜索覆盖表

`harness/coverage.py` 按 (Polymarket 族, universe, target) 数提案次数，进提案上下文。

**这不违反决定 0006**：本表只数 `proposal_locked`，即「提过几次」。
它不读 `evaluation_result`，不读 `verdict_recorded`，也不按「有没有通过事前筛」过滤。
提案计数在读取任何结果之前就已确定；判决计数才是 0006 关闭的通道。
合同测试钉住这一点：覆盖表的任何字段里不得出现判决词。

### 处置二：机制族进菜单

菜单升 `menu-v3`，新增机制族层（配额 6，先于成交量排序的头部层认领名额 ——
先验层与安慰剂层此前正是因为让头部层先挑而配额落空）。
每行带机制叙述、驱动通道、成员的正反构成，以及与其词汇前身的重合度裁断。

**重合度裁断为「重放」的族不进菜单**：`mech:ISR_IRAN`（与 `cand:iran` 在决策网格上
序数一致 0.816）与 `mech:US_SHUTDOWN`（0.883）被排除。把同一次检验换个名字再问一遍，
既浪费预算也污染分母。入选六族：FED_HIKE、RU_UA_CEASEFIRE、FED_DECISION、
US_INFLATION_MONTHLY、HOUTHI_ATTACKS、HURRICANE_LANDFALL。

### 处置三：机制族的资格筛只在 discovery 段统计

现行 `qualify_pm_families.py` 对全档案统计。对机制族沿用它会让霍尔木兹这类
「discovery 段一个成员都没有、2025-26 才活跃」的族通过资格筛并进入搜索菜单，
而模型引用它时特征处处无定义。新规则 `qualify-mech-v1` 阈值与 qualify-v1 相同，
只把统计窗口限定为 discovery，并输出四轴阈值敏感性曲线。八族全部通过。

## 四、提示词此前有 93% 是一节旧提案

实测组装出的提案器提示词 633,755 字符，其中 `memory` 一节 491,641 字符（93%）：
195 条历史规格，每条都带完整的机制叙述段落。模型要在四十多万字的旧提案里找自己的位置。

处置：只有最近 12 条带机制全文，更早的只留 `feature_id` 与步骤形状 ——
「不要重复」需要的是一张清单，不是四十万字的散文。提示词降至 246,890 字符。

## 五、顺带修正的一处账本失实

目标按**后缀**解析，因此在非 sc 的 universe 上，声明的 `sc_ret_next_session`
实际用的是该品种自己的表（求值正确）。但账本只记声明名，
于是 27 条非 sc 的 Study 全部记着 sc 的目标名。现改为声明名与逐品种实解名并列记录。

## 六、尚未做、需人决定的

- **广度的代价形状**：面板（36 品种）上一次评价是**一次**检验，逐品种扫是 **N** 次，
  而地板只增不减且对全族既有结论同时生效：E₂(135)=2.8622 → E₂(188)=2.9658 →
  E₂(270)=3.0756。「任何标的都试」按后一种做法会把旧族地板推过 3.0，
  并追溯抬高全部 135 条既有否定的门槛。这是统计预算问题，由人决定。
- **机制族提案进哪个统计族**：见 M16 §八决定一（甲：新开族；乙：并入事件族；
  丙：留在旧族），逐族裁断已由重合度闸门给出，但选哪条路仍需人拍板。
- 提案层剩余接线：种子包的机制叙述通道（`external_prior`）、
  缺口表与否证登记进语义审计。

## 七、上线前的三项实测核对

1. **方法说明确实到达模型**：探针问「声明原语缺口时三个必填字段叫什么」，
   stdin 里不含这三个名字。回答为 `mechanism, missing_primitive,
   why_existing_primitives_insufficient` —— 只可能来自方法说明。
   一个被静默忽略的参数与一个生效的参数在普通冒烟测试里长得一样，因此这一步必须单独做。
2. **封闭断言在真实规模下成立**：用 claude-opus-5 跑完整的 247,190 字符提示词
   加 4,188 字符方法说明，耗时 164 秒，`num_turns=1`、`tools=[]`、无任何工具调用。
   探针只调用 provider，不写账本，因此不消耗提案分母。
3. **输出契约一次通过**：无需修复重试。而这一条提案本身是新层的直接证据 ——
   它选了 `mech:FED_HIKE:dp`（机制族的构成受控分量）× `ag_dominant_t1`（沪银）
   × `sc_ret_next_session`，并在机制叙述里用了已更正的窗口几何
   （决策时点 08:59 与 20:59 相距 12 小时，故 43200 秒窗口不带偏移在相邻决策间不重叠）。
   在此之前的 196 条提案里，机制族被引用 0 次、沪银被引用 0 次。
