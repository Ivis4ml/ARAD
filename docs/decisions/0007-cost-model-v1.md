# 决定 0007：最小成本模型（M5 v1），candidate 恢复可达

- 日期：2026-08-08
- 状态：已采纳（用户在三个选项中选定 A）
- 触发：用户对「未声明成本模型：不得取 candidate」逐条出现在判决里提出质疑
- 影响：`kernel.py` 的声明推导与新阻塞理由；`demo.py` 的请求构造；EVALUATOR_VERSION 0.4.0

## 背景

成本闸门的动机是旧系统的教训：通过统计门槛的 73 个检验，加成本透镜后净收益为正的
组合 0/114，盈亏平衡倍数中位 47.5。「没有成本模型就不许叫 candidate」防止再走一遍。
但在 M5 建成之前它使 candidate 结构性不可达，且以每条 Study 的阻塞理由形式呈现，
把系统级状态误读为提案缺陷。

## 决定

采纳最小成本模型（方案 A），要点：

1. **参数分两类，来源分开记。**tick_size 是**数据事实**：从 spine 分钟 bar 实测归纳
   （62 品种；方法自检：sc 归纳值与人工录入的权威合约规格一致，0.1）。
   半点差（1 跳）与佣金（名义额 1bp/边）是**声明的保守常量**（假设），
   经人批准写入 `configs/cost_model_v1.json`；修订常量即换版本号。
2. **形态**：round_trip_cost_ret = 2×佣金 + 2×半点差×tick/中位决策价，
   以标签同量纲（对数收益）计。面板取成员品种成本的中位数。
   任何成员缺 tick 或缺价则整体不声明（宁缺勿假）。
3. **评价机语义**：提供 cost_model 即视为已声明（cost_model_missing 消失）；
   digest 纳入 cost_model（换成本表即另一次评价）。新增阻塞理由
   `uneconomic_target`（失效集合 {candidate}）：label 为有符号收益且
   盈亏平衡捕捉率 = 往返成本 / 平均绝对标签 ≥ 1 时记入 —— 即使完美捕捉平均幅度
   也付不起成本。**否定结论不受影响**：经济上不可行不妨碍断言统计上无关系。
4. **非收益 target（rv 等）**：成本随声明记录进证据，但经济闸门不咬合 ——
   波动预测不是可交易主张，成本约束在它转化为交易时另行评估。

## 实测数量级（v1 表）

sc 一次往返 ≈ 5.5bp，au ≈ 2.8bp，三品种面板中位 ≈ 4.9bp。
对 session 级持有（平均绝对收益通常数十 bp），闸门不会误伤正常主张；
它咬合的是平均幅度小于成本的构造。

## 边界

- v1 不含冲击成本与容量：单手边际口径。容量属后续（canonical M5 的「容量与更精确成本」）。
- 常量修订属人的决定；修订不重算已入账证据（digest 使新旧可区分）。
