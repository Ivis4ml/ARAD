# 决定 0008：事件条件研究计划（独立问题族）

- 日期：2026-08-09
- 状态：已采纳（用户指示「继续修复提升，看看怎么解决问题」，方案此前已提出并获继续授权）
- 触发：146 个互异构造在「小时概率 → 下一时段、永远在线、线性斜率」问题族上系统性
  无信号（run22 后 n=120，地板 2.825，无一越线；两个越线者均死于封存段）
- 影响：Proposal 契约新增 event_trigger；build_evaluation 行过滤；run_service_demo
  的 family 参数化；CLI --family

## 判断

预测市场的信息天然是事件性的：概率长期钉着不动，事件来临时跳变。
「永远在线」的检验把 95% 的无事时段与 5% 的事件时段混在同一条回归里，
信号被稀释到与噪声难分（实测置换 exceed 0.3-1.0）。事件条件窗口
把问题换成「概率大幅移动之后的时段，标的的波动/收益是否可预测」——
对着信息真正到达的时刻提问。

## 机制

1. **触发器**（提案的一部分，进 content id）：field / lookback_seconds /
   min_abs_move。在决策时点 t 活跃当且仅当
   |last(<t) − last(<t−lookback)| ≥ min_abs_move，两值取自**严格早于**边界的
   分桶（与特征窗口同一右端点排他约定）。
2. **样本限制是预注册的**：不活跃与不可判的时点记入 preregistered_exclusions，
   不读它们的 outcome。触发只依赖决策前可见信息，不是结果依赖过滤。
3. **独立问题族**：事件条件研究以 `--family` 声明独立族（如
   sc_event_conditional_v1），统计分母从零起、地板从 0.798 起。
   这不是重置旧账 —— 旧族的 120 次检验与地板 2.825 原样保留 ——
   而是为**不同的问题**开新账，与 Alpha-Data 主族/扩展族分账同一纪律。
4. 功效护栏原样生效：min_returns=30 使触发过严（活跃行不足）的提案判
   underpowered；信号事前筛（M13）与成本模型（决定 0007）照常。

## 边界

- 触发器阈值由模型声明并预注册，不由框架代填 —— 「什么算事件」本身是研究假设；
- 跨族复用同一规格需重新走该族的全流程（content id 含触发器，天然区分）；
- 分类法污染（决定 0004）对新族同样封顶，重归纳仍是前置杠杆。
